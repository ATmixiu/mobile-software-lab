## 二、页面功能说明

### 1. 首页（pages/index/index）
- 展示所有用户上传的图片列表，按发布时间倒序排列
- 每条记录显示：用户头像、昵称、地区、图片、发布日期
- 点击用户头像/昵称 → 跳转个人主页
- 点击图片 → 跳转图片详情页
- 右下角悬浮发布按钮 → 跳转发布页
- 支持下拉刷新
- 包含加载状态、空数据状态、错误提示

### 2. 发布页（pages/add/add）
- 支持从相册选择图片或使用相机拍摄
- 图片预览功能
- 上传进度条实时显示
- 上传到微信云存储（独立目录 `lab6/photos/`）
- 上传成功后自动保存记录到数据库 `lab6_photos`
- 显示当前用户的上传历史（三列网格布局）
- 点击历史图片可进入详情页

### 3. 个人主页（pages/homepage/homepage）
- 根据传入的 openid 查询该用户的所有图片
- 顶部展示用户头像、昵称、地区、图片总数
- 图片按最新时间在上排列，三列网格展示
- 每张图片显示日期标签
- 点击图片进入详情页

### 4. 详情页（pages/detail/detail）
- 根据数据库 `_id` 获取单条图片记录
- 展示大图、用户信息、发布日期
- 三大功能：
  - **下载图片**：下载到本地相册，处理权限拒绝情况
  - **分享给好友**：使用 `onShareAppMessage`，分享后可重新进入该详情页
  - **全屏预览**：使用 `wx.previewImage` 全屏查看
- 点击用户信息可进入该用户主页

## 三、云数据库说明

### 集合1：`lab6_photos`（图片主集合）

### 字段说明：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `_id` | String | 数据库自动生成的唯一ID |
| `_openid` | String | 微信自动生成的用户openid（优先使用） |
| `photoUrl` | String | 图片云存储fileID |
| `avatarUrl` | String | 用户头像URL |
| `nickName` | String | 用户昵称 |
| `country` | String | 国家 |
| `province` | String | 省份 |
| `city` | String | 城市 |
| `addDate` | String | 发布日期（格式：YYYY-MM-DD） |
| `createTime` | Date | 服务器时间（用于排序） |
| `title` | String | 图片标题（新增，最多30字） |
| `description` | String | 图片简介（新增，最多120字，可选） |
| `category` | String | 图片分类（新增：风景/美食/校园/萌宠/生活/其他） |

### 集合2：`lab6_likes`（点赞集合，新增）

### 功能说明：
记录用户对图片的点赞行为，实现社区互动功能。

### 字段说明：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `_id` | String | 数据库自动生成的唯一ID |
| `_openid` | String | 点赞用户的openid（自动生成） |
| `photoId` | String | 被点赞图片的_id |
| `userOpenid` | String | 点赞用户的openid（冗余字段，便于查询） |
| `createTime` | Date | 点赞时间 |

### 业务规则：
- 一个用户对同一图片只能点赞一次（通过photoId + userOpenid唯一约束）
- 取消点赞时删除对应用户的点赞记录
- 点赞数通过count查询实时计算，不使用冗余计数字段避免并发错误

### 集合3：`lab6_comments`（评论集合，新增）

### 功能说明：
记录用户对图片的评论，实现社区互动功能。

### 字段说明：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `_id` | String | 数据库自动生成的唯一ID |
| `_openid` | String | 评论用户的openid（自动生成） |
| `photoId` | String | 被评论图片的_id |
| `userOpenid` | String | 评论用户的openid（冗余字段） |
| `nickName` | String | 评论用户昵称 |
| `avatarUrl` | String | 评论用户头像 |
| `content` | String | 评论内容（最多100字） |
| `createTime` | Date | 评论时间 |

### 业务规则：
- 评论按createTime正序排列（最早的评论在最上面）
- 用户只能删除自己的评论，删除前需二次确认
- 评论内容不能为空，去除首尾空格后校验

### 集合4：`lab6_users`（用户资料集合，新增）

### 功能说明：
存储用户个人资料（头像、昵称），实现用户主动选择头像和填写昵称，发帖和评论时自动使用最新用户资料。

### 字段说明：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `_id` | String | 数据库自动生成的唯一ID |
| `openid` | String | 用户唯一标识（手动保存，用于查询） |
| `avatarUrl` | String | 用户头像云存储fileID |
| `nickName` | String | 用户昵称 |
| `createTime` | Date | 资料创建时间 |
| `updateTime` | Date | 资料最后更新时间 |

### 业务规则：
- 每个用户通过openid唯一对应一份资料
- 保存时先查询当前openid是否已有记录，已有则update，没有则add
- 禁止同一个openid重复创建多条用户记录
- 头像上传到独立云存储目录lab6/avatars/，文件名使用openid+时间戳防止冲突
- 昵称必填，trim()校验，长度限制20字
- 没有设置资料时安全降级：默认头像、昵称"匿名喵友"
- 不批量修改历史帖子和评论，新发布的内容自动使用最新资料

### 权限设置：
- 所有集合均设置为"所有用户可读，仅创建者可写"
- 确保用户只能修改/删除自己创建的记录

## 五、云函数说明

### 云函数名称：`getOpenid_lab6`

### 功能：
获取当前微信用户的 OPENID

### 调用方式：
```javascript
wx.cloud.callFunction({
  name: 'getOpenid_lab6',
  data: {},
  success: res => {
    console.log(res.result.openid);
  }
});
```

### 返回值：
```javascript
{
  openid: "用户的openid",
  appid: "小程序appid",
  unionid: "unionid（如有）",
  event: {}
```

- 使用官方 `wx-server-sdk`（版本 ~2.6.3）

- 部署时选择"云端安装依赖"

## 七、为适配新版微信修改

### 1. 用户信息获取 API 适配
- **教材旧写法**：`wx.getUserInfo()` + `open-type="getUserInfo"`
- **问题**：该接口在新版微信中已调整，无法直接获取用户真实头像昵称
- **修改方案**：
  - 使用全局缓存机制，首次进入时从本地存储读取用户信息
  - 如无用户信息，使用默认值（"微信用户"）保证小程序正常运行
  - 后续可通过 `wx.getUserProfile` 或头像昵称填写组件进行补充
  - 业务逻辑不受影响，所有功能均可正常使用

### 2. 图片选择 API 适配
- **教材旧写法**：`wx.chooseImage()`
- **修改方案**：使用新版 `wx.chooseMedia()`，支持更丰富的媒体类型选择
- 保留相册选择和相机拍摄两种来源

### 3. 渲染引擎调整
- 原项目使用 Skyline 渲染引擎和自定义导航栏
- 为保证云开发功能和所有页面的最大兼容性，调整为默认 WebView 渲染引擎和原生导航栏
- 页面功能结构保持一致

### 4. 云函数环境适配
- 使用 `cloud.DYNAMIC_CURRENT_ENV` 动态获取当前环境，无需硬编码环境ID
- 确保在不同云环境下均可正常运行

## 九、可能出现的问题及解决办法

### 问题1：云函数调用失败
- **现象**：控制台报 `cloud.callFunction:fail` 或函数不存在
- **解决办法**：
  1. 确认云函数已正确上传部署（右键云函数 → 上传并部署：云端安装依赖）
  2. 确认云开发环境已开通
  3. 检查 app.js 中云开发初始化配置

### 问题2：数据库查询失败（权限错误）
- **现象**：控制台报 `database collection not exists` 或权限错误
- **解决办法**：
  1. 在云开发控制台手动创建 `lab6_photos` 集合
  2. 设置集合权限为"所有用户可读，仅创建者可写"
  3. 确认使用的是正确的云环境

### 问题3：图片上传失败
- **现象**：`uploadFile:fail` 错误
- **解决办法**：
  1. 确认云存储已开通
  2. 检查网络连接
  3. 确认云存储权限设置允许上传

### 问题4：图片无法显示
- **现象**：图片区域空白或加载失败
- **解决办法**：
  1. 确认 `photoUrl` 是有效的云存储 fileID
  2. 检查云存储文件的读取权限
  3. 确认云环境配置正确

### 问题5：下载图片无反应
- **现象**：点击下载按钮无反应或报错
- **解决办法**：
  1. 确认已在 app.json 中配置相册权限说明
  2. 检查用户是否授予了相册权限
  3. 在真机上测试（模拟器可能不支持保存到相册）

### 问题6：openid 获取不到
- **现象**：`app.globalData.openid` 为空
- **解决办法**：
  1. 确认云函数 `getOpenid_lab6` 已部署
  2. 检查网络连接
  3. openid 获取是异步的，页面中需做延迟获取处理（代码中已包含轮询机制）

## 十二、创新功能（优秀版增强）

本项目在教材基础功能之上，自主扩展了一套完整的"图片社区增强版"功能，将实验从单纯的"图片展示程序"升级为真正具有社区交互能力的图片分享小程序。所有创新功能均使用实验6独立资源（lab6_前缀），不影响原有云环境。

### 功能分类说明

#### 【实验教材要求功能】
1. 云开发初始化（app.js中wx.cloud.init）
2. 云函数获取openid（getOpenid_lab6）
3. 云数据库操作（lab6_photos增删改查）
4. 云存储上传（lab6/photos/目录）
5. 首页图片列表展示（按时间倒序）
6. 图片详情页（大图展示）
7. 个人主页（按用户筛选图片）
8. 图片下载（wx.cloud.downloadFile + wx.saveImageToPhotosAlbum）
9. 分享功能（onShareAppMessage）
10. 全屏预览（wx.previewImage）

#### 【自主扩展创新功能】

##### 1. 图片标题、简介与分类标签
- **功能说明**：发布图片时增加标题（必填，最多30字）、简介（可选，最多120字）、分类（必选，固定为风景/美食/校园/萌宠/生活/其他）
- **技术实现**：发布页增加表单输入，数据写入lab6_photos集合的title/description/category字段
- **老数据兼容**：旧记录无这些字段时，title默认显示"图片分享"，category默认显示"其他"，description为空时不显示简介区域
- **创新价值**：从单纯的图片上传升级为带内容描述的社区分享，提升信息丰富度

##### 2. 分类浏览
- **功能说明**：首页顶部增加横向分类栏（全部/风景/美食/校园/萌宠/生活/其他），点击分类后只显示对应类别的图片
- **技术实现**：分类切换时通过数据库where条件筛选，同分类内仍按createTime倒序排列
- **空状态处理**：某分类无图片时显示"这个分类暂时还没有图片"
- **创新价值**：提供内容分类导航，提升内容发现效率

##### 3. 关键词搜索
- **功能说明**：首页顶部增加搜索框，支持根据标题、简介、分类、用户昵称进行关键词搜索
- **技术实现**：采用客户端过滤方案（先获取已加载图片，再在客户端进行关键词匹配），无需建立复杂云索引；加入300ms debounce避免频繁刷新
- **组合查询**：搜索与分类筛选可共同工作（如先选"校园"分类再搜索"图书馆"）
- **创新价值**：提供内容检索能力，提升用户查找特定内容的效率

##### 4. 图片点赞系统
- **功能说明**：详情页增加点赞按钮，用户可对图片点赞/取消点赞，点赞数实时更新
- **技术实现**：
  - 新建独立集合lab6_likes，每条记录保存photoId、userOpenid、createTime
  - 一个用户对同一图片只能点赞一次（photoId + userOpenid唯一约束）
  - 点赞数通过count查询实时计算，不使用冗余计数字段避免并发错误
  - 取消点赞时删除当前用户自己的点赞记录，禁止删除其他用户点赞
  - 所有点赞操作均有失败回滚机制，数据库写入失败时UI不假装成功
- **创新价值**：从单向内容展示升级为双向社区互动，是"图片分享社区"的核心交互功能

##### 5. 图片评论系统
- **功能说明**：详情页下方增加评论区，用户可发表评论、查看所有评论、删除自己的评论
- **技术实现**：
  - 新建独立集合lab6_comments，每条评论保存photoId、userOpenid、nickName、avatarUrl、content、createTime
  - 评论按createTime正序排列（最早的评论在最上面）
  - 评论内容校验：不能为空、去除首尾空格、最长100字
  - 评论成功后清空输入框并立即显示新评论
  - 评论失败时保留原输入内容并提示"评论失败，请重试"
  - 用户只能删除自己的评论，删除前通过wx.showModal二次确认
  - 不做评论回复、楼中楼、@用户等复杂功能，避免无意义复杂度
- **创新价值**：提供用户间内容讨论能力，增强社区互动深度

##### 6. 用户主页数据统计
- **功能说明**：个人主页顶部增加统计栏，显示该用户的作品数、获赞数、分类数
- **技术实现**：
  - 作品数 = 该用户在lab6_photos中的记录数量
  - 获赞数 = 该用户所有图片在lab6_likes中获得的点赞总数（通过photoId批量查询）
  - 分类数 = 该用户作品中不同category的数量
  - 所有统计数据均实时计算，不写死
  - 数据为0时正常显示0，不允许出现undefined
- **创新价值**：提供用户成就展示，增强个人主页的信息密度和社区属性

##### 7. 分页加载与下拉刷新
- **功能说明**：首页图片列表采用分页加载（每页10条），上拉触底自动加载下一页，下拉刷新重置列表
- **技术实现**：
  - PAGE_SIZE = 10，首次加载limit(10)
  - 上拉触底时通过skip(page * pageSize) + limit(10)加载下一页
  - 使用isLoading和hasMore状态控制，防止重复请求、重复数据、连续触发加载
  - 下拉刷新时清空当前数据，page重置为0，hasMore重置为true，重新获取第一页
  - 页面底部显示"正在加载……"和"已经到底啦"状态提示
- **创新价值**：工程优化，提升大数据量下的加载性能和用户体验

##### 8. 新版微信API适配
- **功能说明**：针对新版微信API政策调整，对教材旧代码进行兼容性适配
- **技术实现**：
  - 用户信息获取：教材旧写法wx.getUserInfo + open-type="getUserInfo"在新版微信中已调整，采用全局缓存+默认值机制保证小程序正常运行，后续可通过wx.getUserProfile或头像昵称填写组件补充
  - 图片选择：教材旧写法wx.chooseImage()升级为新版wx.chooseMedia()，支持更丰富的媒体类型选择
  - 渲染引擎：原项目使用Skyline渲染引擎和自定义导航栏，为保证云开发功能最大兼容性，调整为默认WebView渲染引擎和原生导航栏
  - 云函数环境：使用cloud.DYNAMIC_CURRENT_ENV动态获取当前环境，无需硬编码环境ID
- **创新价值**：保证代码在当前微信版本下可正常运行，体现对技术生态变化的适应能力

##### 9. 完善的异常和空状态处理
- **功能说明**：所有页面均包含完善的状态管理和异常处理
- **技术实现**：
  - 加载状态：所有数据加载均有loading提示
  - 空数据状态：首页空数据、分类空数据、搜索无结果、个人主页无图片、详情页无评论等均有友好的空状态提示
  - 错误提示：网络错误、权限错误、操作失败等均有明确的错误提示和重试机制
  - 按钮防重复提交：点赞、评论、发布等按钮均有submitting/processing状态锁，避免重复提交
  - 权限处理：下载图片前主动检查相册权限，用户拒绝时友好引导到设置页
  - 老数据兼容：所有新增字段均有安全默认值，页面中禁止出现undefined、null、NaN、[object Object]
- **创新价值**：提升程序健壮性和用户体验，体现工程严谨性

##### 10. 用户个人资料系统
- **功能说明**：支持用户主动选择头像和填写昵称，建立独立的用户个人资料系统，实现发帖和评论时自动使用最新用户资料
- **技术实现**：
  - 新建独立集合lab6_users，每个用户通过openid唯一对应一份资料
  - 保存时先查询当前openid是否已有记录，已有则update，没有则add，禁止同一个openid重复创建多条记录
  - 头像选择使用当前微信支持的<button open-type="chooseAvatar">用户主动选择方式
  - 头像上传到独立云存储目录lab6/avatars/，文件名使用openid+时间戳防止冲突
  - 昵称输入使用当前小程序支持的<input type="nickname">，必填，trim()校验，长度限制20字
  - 个人主页增加"编辑资料"按钮，只有当前访问用户openid==当前登录用户openid时才显示
  - 首次使用兼容：获取openid后自动查询lab6_users，没有资料时不阻止浏览，默认使用"匿名喵友"和默认头像
  - 发帖联动：发布图片时优先读取lab6_users中的avatarUrl和nickName，没有资料时安全降级
  - 评论联动：发表评论时同样优先使用lab6_users中的最新资料
  - 个人主页显示最新资料：头像和昵称优先从lab6_users获取，查不到时使用帖子中的旧头像昵称或默认值
  - 不批量修改旧帖子：历史记录保持原样，个人主页读取最新资料即可，新发布的帖子和新评论自动使用新资料
  - 防重复提交：保存资料时增加saving状态锁，用户点击保存后按钮禁用，保存完成或失败后恢复
  - 错误处理：处理用户取消头像选择、头像上传失败、昵称为空、查询失败、保存失败、网络异常等情况
- **创新价值**：从默认用户信息升级为完整的用户个人资料系统，提升社区用户身份认同感，体现对新版微信API的适配能力

## 十三、UI与交互设计优化

### 1. 从微信默认绿色风格升级为暖色奶油主题

#### 配色方案
- **全局背景**：#F7F5F2（暖灰奶油色），替代原纯白整屏
- **卡片背景**：#FFFFFF
